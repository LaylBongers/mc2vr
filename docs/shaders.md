# Reimplemented shaders

The game's shaders rewritten as HLSL (`src/carrier/reimpl/shaders/`), compiled at build time with Microsoft's `d3dcompiler_43` ([build.md](build.md#hlsl-shader-compiler)) and substituted when the game creates the originals. Like the C++ reimplementations ([reimpl.md](reimpl.md)), they read like the originals and change what needs changing.

## Mechanism

- **Substitution:** the glue is in `hooks/shader_reimpl.cpp`, the shader counterpart of `hooks/reimpl.cpp`. It holds the replacement list, one line per shader, and the HLSL in `reimpl/shaders/` is the reimplementation itself. The device's `CreatePixelShader` (vtable slot 106, `hooks/device.cpp`) passes each creation's bytecode to `hooks::shader_reimpl::substitute_pixel_shader`.
  - It hashes the bytecode (FNV-1a over the token stream up to the end token, as `tools/shader_hash.py`).
  - For a reimplemented original it returns our bytecode instead.
  - The game keeps the object it gets back, so its caches stay consistent ([hooks.md](hooks.md)).
  - If the device refuses ours, the original is created and the entry is disabled (logged as an ERROR).
- **The interface stays the original's:** the same input semantics, the constant names at the same registers (explicit `register(cN)`), the same samplers. The game resolves and uploads constants by name, so it drives ours unchanged.
  - Check: `tools/shader_iface.py <game>/data/shader3.bin`. For every registry entry it compares the generated bytecode (`build/win32/generated/shaders/<name>.h`) with the original (`shader3.bin@offset`):
    - the input and sampler declarations;
    - every constant-table entry (name, register set, register, count);
    - the static `if bN` structure, with empty `else` arms dropped, since their placement is codegen;
    - the registry hash against the container.
    It doesn't check the math.
  - **Math:** `tools/shader_equiv.py <game>/data/shader3.bin` checks the math. It emulates each original and ours, as SM3 bytecode in numpy, on 1000 random trials, and compares the outputs to 1e-4.
    - **Inputs:** random inputs, constants and bools, so every light-count branch gets covered. The light constants are drawn in plausible ranges.
    - **Samplers:** each mocked as a smooth function of its UV. The sun shadow map is mocked as one constant depth per trial, so the 1-tap and 9-tap lookups agree and any difference is a porting error.
    - **Blind spots:** the shadow-map UV side (cascade u/v rows, tap offsets, the 9-tap's bilinear weights), constants that never reach the output (the 30000 clamp), and real screen-space derivatives (`dsx`/`dsy` are mocked). Those need checking in game.
    - **Options:** `--self` compares each original with itself; `--perturb neg|def[:K]` corrupts ours, to show it gets caught.
    - **Tested (2026-11-13):** a deliberate reflection-weight × 0.9 and a shoreline factor of 0.95 → 0.96 in PgWaterFPDWE were both caught.
    - Run both tools after every shader change. Each takes well under a second.
- **Debug tools:** tools that hash the bound shader (`ps_census`, `camera_census`) see our bytecode's hash for replaced shaders, not the original's.
- **Conf:** `shader_reimpl=on|off`, default on. Off gives the originals, for A/B.
- **Log:**
  - `shaders: <hash> <name> -> reimplementation` at each substitution.
  - `shaders: window:` with the substitution counts per entry, logged only when shader creations happened.

| **PgUnderwaterFP** (`@0x24f4d0`): `edb3eaee` | `PgUnderwaterFP.hlsl` | the same. Wake-masked (`texkill`) surface seen from below: Blinn-Phong specular, and a Fresnel blend with a projected refraction offset by the normal |
| **PgWaterFPDWE** (`@0x254a80`): `c2dde179` | `PgWaterFPDWE.hlsl` | the same. Hand-filtered 128² wake mask, then:<br>• water thickness from `DepthMap` via `ProjectParams` (refracted point, with fallback), looking up `DepthColorMap`;<br>• refraction, then reflection by Fresnel⁵ · `materialData[5].x`;<br>• a shoreline blend back to the screen refraction.<br>The original was compiled with little optimization: 2516 tokens, ours 915 |
| **PgWaterFP** (`@0x2571d0`, `06f59bd8`), **PgWaterFPbl** (`@0x24fe80`, `dcf34dbd`), **PgWaterFP_LI** (`@0x25c3d0`, `7050482e`) | `PgWaterFP.hlsl`, one source built three ways (`MC2VR_WATER_BL`, `MC2VR_WATER_LI`) | the same. Each draws:<br>• two sets of four Gerstner-style waves (`Waves[0..11]`), each set under a dynamic branch and faded by the pixel footprint `length(ddx + ddy)` of the world xz;<br>• the wake normal and foam (`WakeNormalMap`, `WakeFoamMaskMap`, `FoamMap`);<br>• then the PgWaterFPDWE-style depth colour, refraction, reflection and shoreline.<br>FP filters the wake maps bilinearly by hand; bl samples them once; LI has no foam mask, drops the shoreline lerp and doesn't zero masked rgb |

- `global_light.hlsli`: `globalLightData`'s layout and the ambient cube: six colours `[3..8]` picked by the normal's signs, weighted by N².
- `shadow.hlsli`: the shared sun-shadow lookup, cascade selection and the 9-tap kernel, transcribed from the high-quality receiver `shader3.bin@0x11570`.
- `lights.hlsli`: the local lights.
  - **Point light** (3 registers: position, colour, attenuation): `saturate(dist·x + z) · colour · N·L`.
  - **Spot light** (4 registers): a distance falloff and a cone falloff, each a `pow` by the light's exponent, zero behind the light, times N·L.
- **Variants:** each family comes in 7, built from one source with defines (`src/carrier/CMakeLists.txt`). The generated symbols carry the originals' file names: `PgFastFP`, `PgFastFP_pl`, `_pl_li`, `_pl_sl`, `_pl_sl_li`, `_sl`, `_sl_li`. They are no local lights, or point and/or spot lights in one of two counting schemes:
  - **plain** (`_pl`, `_sl`, `_pl_sl`): the highest set bool picks the count. Points take 8/4/2/1 by `b3`/`b2`/`b1`/`b0`; spots take 4/2/1 by `b6`/`b5`/`b4`.
  - **`_li`** (`MC2VR_LIGHTS_LI=1`): 2 lights always, +2 if `b2` (points) or `b6` (spots), and points +2 more if `b3` is also set.
  - The two families differ only in their inputs. The distant one doesn't normalize the normal or saturate the direct light; the near one saturates sun plus local lights.

## Cost

A/B in one spot (2026-11-13, HMD, gameplay, last ~30 s of each run; per frame, both eye passes):

| | Pixels | Draws | GPU, original (1 tap) | GPU, ours (9 taps) |
|---|---|---|---|---|
| PgFastFP | 2.02 Mpix | 380 | 0.50–0.57 ms | 0.54–0.61 ms |
| PgScrubLightFP | 0.5 Mpix | 332 | 0.065 ms | 0.06 ms |

- The difference is about +0.05 ms, within the window-to-window spread.
- Frame GPU was ~10.4 ms in both runs.
- The extra taps hardly cost anything: the shader is dominated by its overdraw, and neighbouring point-sampled taps hit the cache. So there's no need for fewer taps or hardware PCF on cost grounds.

## OPEN

- **Live (2026-11-13), the two sun-only vegetation shaders:**
  - They substituted at load: vegetation 13 creations, distant 5. No errors.
  - Vegetation shadows look better, and nothing came out unlit. So the `float4`-typed constant arrays (the originals' CTAB says `void`) don't matter to the game.
- **Live (2026-11-13), all 14 vegetation variants:** substituted at load with no errors, 90 Hz held, nothing visibly wrong. The 12 lit variants draw only near the game's point and spot lights. Those are hard to pin down in play, so the lit paths were not specifically observed: accepted as working, revisit if vegetation lighting looks wrong near fires or lamps (A/B with `shader_reimpl=off`).
- OPEN, live check (2026-11-13): PgBillboardTreeFP and the 7 PgDecal2FP variants pass the interface check but haven't run in game. Distant trees and decals should look unchanged apart from softer shadow edges. The decals draw rarely, at certain places: indoors at the start was one.
- **Math, all 24 replacements (2026-11-13):** `shader_equiv.py` finds 0 differing, max error ~1e-16. That includes the 12 lit vegetation and 6 lit decal variants that couldn't be observed in game.
- **All 27 single-tap receivers are reimplemented (2026-11-14):** both checks pass on every one. `shader_equiv.py` mocks `dsx`/`dsy` as an affine function, and enlarges the `Waves` footprint scales so the wave branches run.
- OPEN, live check: the five water shaders (PgUnderwaterFP, PgWaterFPDWE, PgWaterFP, PgWaterFPbl, PgWaterFP_LI). Water should look unchanged apart from softer sun-shadow edges: waves, foam, wakes, shoreline and refraction.
- Names of the originals: [reverse_engineering/shader_containers.md](reverse_engineering/shader_containers.md). The light-variant suffixes are `_pl`/`_sl`/`_pl_sl`, plus `_li` versions.
